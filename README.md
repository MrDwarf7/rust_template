# rust_template (cargo-generate experiment)

Trial version of `rust_template`, published on the `cargo-generate` branch
of the same repository. The existing `main` template stays unchanged while
this subfolder layout is tested before deciding whether to replace it.

Server flavor is **not** in this experiment. That comes after cli +
workspace + ws_crate, from `rpa_lite` / `agent_axum.rs`.

## Prerequisites

Install Rust/Cargo and **cargo-generate 0.24+** before using the commands
below. cargo-generate is separate from Cargo.

With Cargo, follow the
[official cargo-generate installation instructions](https://cargo-generate.github.io/cargo-generate/installation.html):

```bash
cargo install cargo-generate --locked
```

Or use [mise's Cargo backend](https://mise.jdx.dev/dev-tools/backends/cargo.html):

```bash
mise use --global cargo:cargo-generate@latest
```

This installs cargo-generate and adds it to your global mise configuration.
Use a mise-activated shell so the command is on `PATH`. For installation only,
use `mise install cargo:cargo-generate@latest` instead.

Generated `cli` and `workspace` projects include a `mise.toml` that requests
latest development tools with an explicit 24-hour minimum release age. This
holds back newly published versions. After generation, run
`mise trust && mise install && mise reshim` from the project root.
`rust-toolchain.toml` continues to own the Rust toolchain version.

Check that cargo-generate is available before generating:

```bash
cargo generate --version
```

## Generate

Test the published branch without changing the default template:

```bash
cargo generate --git https://github.com/MrDwarf7/rust_template \
  --branch cargo-generate cli --name my_app
cargo generate --git https://github.com/MrDwarf7/rust_template \
  --branch cargo-generate workspace --name my_ws
```

To add a member from that branch, run from an existing workspace root:

```bash
cargo generate --git https://github.com/MrDwarf7/rust_template \
  --branch cargo-generate ws_crate --name extra_crate --destination crates
```

The favorites below also select `cargo-generate`, not `main`.

From this directory:

```bash
# prompts for which sub-template if you omit the name
cargo generate --path . --name my_app

# skip the picker
cargo generate --path . --name my_app cli
cargo generate --path . --name my_ws workspace
```

Or use the favorites in [`favorites.toml`](favorites.toml) (merge into
`~/.cargo/cargo-generate.toml`, or pass `--config`):

```bash
cargo generate rt-cli --name my_app
cargo generate rt-workspace --name my_ws
cargo generate rt-crate --name extra --destination crates
```

In a workspace generated by this template, add a library crate from its root:

```bash
cargo make wsa authentication
```

Pass the bare name; `wsa` prepends `<CRATE_PREFIX>-` when the prefix is set,
so `wsa authentication` in an `acme` workspace creates
`crates/acme-authentication`. `CRATE_PREFIX`, `PERF_TESTING` and
`AGENT_SUPPORT` are written to `Makefile.toml` `[env]` at generation time and
forwarded to `ws_crate`; edit them there to change what later crates get.
`wsa` is a plain cargo-make `command`/`args` task (`build/workspace-tasks.toml`)
and is skipped with a usage message when no name is given or the current
directory is not a workspace root.

The template source defaults to
`--git https://github.com/MrDwarf7/rust_template --branch cargo-generate`.
Override it with `RT_TEMPLATE`, split on spaces, e.g.
`RT_TEMPLATE="--path /abs/path/to/rust_template" cargo make wsa auth`
(paths containing spaces are not supported).

`ws_crate` is library-only. Direct cargo-generate calls with a prefix must
pass the fully prefixed `--name` because hooks cannot rename the output dir:

```bash
cargo generate --path /path/to/rust_template ws_crate \
  --name acme-authentication --destination crates -d crate_prefix=acme
```

`cargo-generate` 0.24+ appends a new path to explicit `[workspace].members`;
`members = ["crates/*"]` already covers the crate. `--no-workspace` skips
auto-add, which pretty-prints the root `Cargo.toml` and can discard comments.
With cargo-generate 0.25, explicit-member workspaces using `trim-paths`
should use `--no-workspace` and add the member manually.

## Rust toolchain

Generated projects intentionally default to the **nightly** toolchain, selected
by `rust-toolchain.toml`. Rust has strong stability guarantees, so nightly
rarely breaks code that already worked (the occasional compiler tantrum is not
the usual case).

To switch channels (for example, to `stable`), edit `channel` in
`rust-toolchain.toml` **before the first build**. Remove or replace any
nightly-only settings first: Cranelift's `codegen-backend`, its
`cargo-features = ["codegen-backend"]` declaration, and its
`rustc-codegen-cranelift-preview` component; any `trim-paths` setting
that your selected Cargo does not support, unstable options in `.rustfmt.toml`,
and `-Z` flags. `trim-paths` is stable in recent Rust releases; check that your
chosen toolchain supports it.

## Sub-templates

| folder      | what you get                                                                                                                                     |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `cli`       | single-crate app (bin)                                                                                                                           |
| `workspace` | virtual workspace (`resolver = "3"`, profiles + `[workspace.package/dependencies/lints]` at the root) + `crates/<name>/`; optional extra members |
| `ws_crate`  | library-only workspace member; keeps `error` private and exposes namespaced error aliases                                                        |

Workspace member names are used verbatim as directory and Cargo package names:
`acme-core` stays `acme-core`, and `acme_core` stays `acme_core`. Extra names
are trimmed but not case-converted. With `crate_prefix`, a `-` is added unless
the name already starts with `<prefix>-` or `<prefix>_`; for example,
`crate_prefix = "acme"` and `extra_crates = "api, acme_db"` create
`acme-api` and `acme_db`. Duplicate detection compares Rust's normalized
snake-case library names, so equivalent spellings are not added twice.
The first crate keeps the project name. Every member `Cargo.toml` is written
by `hooks/workspace/post.rhai` from one template, so they cannot drift.

Inside a crate, use `Error` and `Result` from its private `error` module. The
public API exports only namespaced aliases. For `acme-authentication` with
`crate_prefix = "acme"`, `src/lib.rs` exports:

```rust
pub use crate::error::{Error as AuthenticationError, Result as AuthenticationResult};
```

Rhai derives `crate_namespace` by stripping `crate_prefix` from
cargo-generate's snake-case `crate_name` and converting the remainder to
UpperCamelCase. With an empty prefix, the whole crate name is used.

### Coding agents

When `agent_support` is enabled, generated project roots and workspace members
include scoped `AGENTS.md` guidance and `.agents/skills/`. A one-line
`CLAUDE.md` import exposes these rules to Claude Code's default project
instructions setup; OpenCode and oh-my-pi discover the agent skill layout
directly. When disabled, these files and the agent-only docs setup guide are
omitted.

The `docs-upkeep` skill creates pages with
`uv run scripts/update-docs-index.py --new "<Title>"`, then updates relevant
docs and regenerates/checks the index.

The generated `mise.toml` includes `uv` for its PEP 723 PyYAML dependency.
Hotpath skills are included only when both `perf_testing` and `agent_support`
are enabled.

Descriptions and author text are escaped for TOML strings, including quotes,
backslashes, control characters, and Unicode. The original values remain
unchanged for README text and URLs.

### Linker

The Linux-only `linker` prompt sets project linker profiles in `.mbx.toml`.
`default` leaves Cargo's linker choice unchanged; `lld` selects the active
toolchain's `rust-lld`. `mold` and `wild` select `mold@3.0.0` and
`wild@0.10.0`; mbx downloads and verifies these linkers itself
([managed linker docs](https://mr-boxington.jdx.dev/linkers)). Mise can install
mold, but has no Wild registry entry, so the project uses one linker owner:
mbx. No generated `.cargo/config.toml` `-fuse-ld` flags overlap with mbx.
`bfd` and `gold` are not mbx-managed selectors, so they are not offered here.
All non-system selections run through `clang`, which must be on `PATH`; the
Linux CI setup action installs it.

Plain `cargo` without mise or mbx ignores `.mbx.toml` and uses rustc's default
linker, so it still builds. The generated `.gitignore` ignores
`.cargo/config.toml` for optional local Cargo settings; `.mbx.toml` is tracked
to share linker profiles with the project.

### Build tools

Tool probes and install prompts have been removed. The project `mise.toml`
files request the latest development tools and set a 24-hour release age.
In a generated project, run:

```bash
mise trust && mise install && mise reshim
```

This installs cargo-make, taplo, git-cliff, bacon, cargo-deny, cargo-nextest,
mbx, cargo-watch, cargo-edit, typst, rumdl, and uv. rumdl reads the
checked-in `.rumdl.toml`. The workspace config also includes cargo-generate
for its `wsa` task. The mise wrapper routes plain `cargo` through mbx; without
mise, plain `cargo` still uses rustc directly. `cargo make A` formats, checks,
lints, builds (debug and release), and tests the project.
The cargo-make tasks call `${CARGO_CMD}`, which defaults to `mbx` (cargo-make
drops mise's cargo wrapper from `PATH`). Without mbx, run
`CARGO_CMD=cargo cargo make <task>`.
GitHub build, test, and docs workflows run compiler commands through the
official [mbx Action](https://mr-boxington.jdx.dev/github-action), pinned to a
full commit SHA. Draft release builds use its `local` backend.

### Performance testing

The `perf_testing` placeholder defaults to `false`. When enabled, each crate
gets an example Criterion benchmark in `perf/`; for binary crates it benchmarks
standalone example work, not the binary's private implementation. Run
`cargo bench` to execute it. Mise also installs `cargo:hotpath` with its TUI,
cloud, and utils features, plus `cargo:samply` for hotpath CPU profiling.
When disabled, generated projects omit `perf/`, Criterion, and the hotpath
tools. Workspace `wsa` forwards this setting when any member has `perf/` or
the root `mise.toml` lists hotpath.

## Hooks

All Rhai lives in `hooks/` at the repo root (a `hooks/` dir inside a
sub-template would be left behind, empty, in the output):

| file                              | stage    | used by                                          |
| --------------------------------- | -------- | ------------------------------------------------ |
| `hooks/init.rhai`                 | init     | cli, workspace (Linux linker prompt condition)   |
| `hooks/pre.rhai`                  | pre      | cli, workspace                                   |
| `hooks/toml.rhai`                 | pre      | cli, workspace, ws_crate (TOML string escaping)  |
| `hooks/finish.rhai`               | post     | cli, workspace (VCS init and build-system notes) |
| `hooks/workspace/{pre,post}.rhai` | pre/post | workspace                                        |
| `hooks/ws_crate/pre.rhai`         | pre      | ws_crate                                         |
| `hooks/ws_crate/post.rhai`        | post     | ws_crate                                         |

Preference order: `cargo-generate.toml` builtins (placeholders,
conditionals, `.genignore`) -> Rhai builtins (`variable::`, `file::`) ->
`system::command` only where the sandbox has no builtin: VCS init and copying
extra workspace crates (`file::` has no read or copy).

`--allow-commands` skips the per-command approval prompt. A silent one-crate
generate with `vcs_kind=none` runs no commands that matter.

Template logos/icons are dropped by the cli and workspace `.genignore` files;
`assets/generate-assets.sh` stays so projects can make their own.

GitHub Actions `${{ }}` is wrapped in `{% raw %}` so Liquid does not
eat it. git-cliff's Tera body is also `{% raw %}`'d; only the `<REPO>`
URL is Liquid.

## Updating an existing project

```bash
cd /path/to/existing_project
python3 /path/to/rust_template_cargo_generate/update-existing.py --dry-run
python3 /path/to/rust_template_cargo_generate/update-existing.py
```

Renders the matching sub-template (detected from `Cargo.toml`, or
`--kind`) with the project's name and VCS, then copies only files the
project is missing. `src/`, `crates/`, `Cargo.toml`, `README.md`, etc. are
never touched. Extra `cargo generate` args go after `--`.

## What this does not do yet

- `server` sub-template (later, from rpa_lite)
- Shipping as the GitHub "Use this template" default
- Precompiled Rhai bytecode: cargo-generate only loads `.rhai` source.

## Generator regression test

Requires Python 3.11+ and cargo-generate. Run from this checkout:

```bash
python3 -B -m unittest discover -s tests -v
```

Generates disposable CLI, workspace, and library-member projects.
Checks TOML round-trips, workspace member generation, perf/agent support
gates, docs-index generation, and Liquid rendering. It does not compile or run
the generated applications.
Each generated crate includes one integration smoke test. Run `cargo test` and
`cargo clippy --all-targets` from the generated project to exercise it.

  -d vcs_kind=none \
